## 2. 다음 단계 (추천 순서)

### 1단계 — 매일 쓰는 기능 다듬기 (1~2주)
1. **카테고리별 예산**: 식비·교통 등 항목별 월 예산과 남은 금액. 저장 데이터에 새 항목(`budgetsByCategory` 등)을 **추가만** 하고, 백업 검증(`fmValidateBackup`)과 복원 테스트를 함께 갱신합니다.
2. **반복 거래 확인**: 반복 거래는 이미 매달 자동으로 기록됩니다(`syncRecurring`). 이번 달 자동 기록된 항목을 홈에서 보여주고, 금액이 달라졌으면 바로 고칠 수 있게 합니다.
3. **거래 검색 개선**: 기간·금액 범위 필터.

### 2단계 — 자산 흐름 보기 (2~3주)
1. **월별 순자산 추이**: 이미 매일 쌓이는 `dailySnapshots`로 12개월 그래프와 전월 대비 변화를 보여줍니다.
2. **자산 구성 변화**: 계좌 종류별 비중을 월별로 비교합니다.
3. **현금·부채를 계좌 방식으로 옮기기**: 기존 "기존 자산 이전" 기능을 자산 화면에서 안내합니다. 데이터는 사용자가 직접 확인한 뒤에만 옮깁니다.

### 3단계 — 데이터 안전 (상시)
1. **백업 파일 버전 관리**: 백업 파일 이름에 시각을 넣고, 복원 전에 현재 데이터를 자동으로 내려받습니다.
2. **브라우저 혼용 경고**: 삼성 브라우저와 Chrome은 데이터가 따로 저장됩니다. 데이터가 비어 있는데 백업이 있는 상태로 보이면 "다른 브라우저에 데이터가 있을 수 있어요"라고 안내합니다.
3. 실제 Android 기기에서 PWA 업데이트와 공유 백업을 정기적으로 확인합니다(자동 테스트로는 확인할 수 없음).

### 4단계 — 코드 정리 (ChatGPT와 역할 합의 후)
1. 스타일 블록 86개, `!important` 738개를 화면별 CSS로 정리합니다. 정리할 때마다 스크린샷이 픽셀 단위로 같은지 비교합니다(PR #46에서 쓴 방식).
2. `index.html` 한 파일(약 57만 글자)을 CSS·JS 파일로 나눕니다. 서비스 워커 `ASSETS` 목록과 `validPage` 검사를 함께 바꿔야 하므로 PWA 업데이트 테스트를 먼저 보강합니다.
3. 오래된 Draft PR #6(v3.0.41 기준)은 현재 main과 크게 달라서, 닫고 필요한 부분만 새로 가져오는 것을 제안합니다.
4. 저장소 맨 앞의 작업 기록 문서(`*_STATUS.md` 19개)를 `docs/status/`로 옮깁니다.
