## 원작 식별 및 실제 확인
기존 작업 기록과 2011년 MobCrete Pucca's Restaurant/Pucca n' Friends를 기준으로 한다. Noodle Rush나 후속 음식 트럭 게임과 혼합하지 않았다.

- 실제 화면을 내려받아 시각 검사: https://news.macgasm.net/wp-content/uploads/2011/05/IMG_6523-e1305559283502.png . 회색 조리대·목재 서빙대·완성 음식과 큰 머리/작은 몸 캐릭터를 확인했다. 이 이미지는 관찰용이며 게임 번들에 복사하지 않았다.

## 구현 경계와 보존
- 게임 번들 v1.1.0. 기존 v1/v2 키 유지. 기존 v2 루트 스키마/필드 보존, `service:{version:1,stock:[...],guests:[...]}`만 첫 서빙 동작 시 추가한다. 기존 조리 인덱스·ends·coins·served·level·decor·roomLayout·알 수 없는 필드 유지.
- 저장은 한 v2 JSON의 원자적 갱신. 식사 정산 때 coins/served/paid/phase를 함께 저장하고 실패 시 모두 복구한다. 다시 열어도 paid 상태를 재지급하지 않는다.
- 재고는 원작 접시 수를 임의 생성하지 않고 기존 보상을 한 배치 단위로 보존한다. 정산 단계가 재개될 때 남은 연출은 현재 단계 처음부터 재생될 수 있으나 요리 시간과 금액은 바뀌지 않는다.
- 동작 시간(입장2.5초/전달3초/식사4.5초/퇴장2.5초)은 이 구현의 조작 검증용 보정값. 원작 실측치가 아니다. 직원 수/고용/레벨 수치·새 강화·추가 게임·음악은 추가하지 않았다.
- 금융 HTML/서비스워커/수박게임 파일 변경 없음. 엔진은 레스토랑 진입 시에만 로드되고, arcade 경로의 기존 network-first/offline 캐시 수명주기를 사용한다.

## 검증
- 기존 레스토랑4 회귀를 새 서빙 동작에 맞춰 갱신하고 추가2로 대기열/모달 중단/저장 실패 정산 재시도·미지원 서비스 버전 보존 검사. 초기6 통과. 추가로 배포 중 구버전 HTML/새 room JS 조합의 호환 회귀를 확인해 최종7 통과.
- 해당 브랜치 전체 E2E91 통과(기존89+레스토랑2). 금융3·PWA/저장 보존 검사는 최종 결합 CI에서 추가 금융 회귀1과 전환 호환 회귀1을 포함한93 및 금융3을 확인한다.
- 실제60초 타이머로 새 요리3개 시작→서빙→판매: 84.375초, 시작500코인−재료9+보상36=527코인, 판매3, 페이지 오류0.
- 가속 반복20회/조리60/판매60: 최종1040코인, 알 수 없는 필드·금융/수박 마커 보존, 동적 인물 수 bounded, 페이지 오류0. 실제 단말 FPS/메모리 안정성의 증명으로 사용하지 않는다.
- 320/360/390/430 및 가로 화면의 실제 터치·회전 크기·편집 중단·완성금액·가로 넘침 검사와 렌더 확인. 실제 기기의 터치 감각·성능, 원작과 같은 속도/품질은 미검증.

완료 범위는 원작에서 확인된 조리·서빙 운영 흐름의 개선이다. 원작 전체 재현 완료로 선언하지 않는다. 다음 작업은 근거가 없는 수치를 추가하는 대신 메뉴별 수량/가격/숙련/폐기/고용의 실제 자료와 연속 영상을 확보한 범위에서 진행한다.

배포 전환 호환: 구버전 문서가 새 room 스크립트를 늦게 받는 상황을 재현했다. 기존 bridge에 없는 service 메서드는 선택적으로 호출해 기존 조리/모달/뒤로가기를 유지한다. 테스트는 git 이력에 의존하지 않는 고정 구버전 fixture를 사용한다.

## v1.2.0 · 사용자 제공 화면과 가로 구성 대조
2026-10-19 사용자가 첨부한 원작 화면(분홍/청록 벽, 목재 바닥, 회색 조리대, 흰 서빙대, 작은 큰머리 캐릭터)을 직접 보며 수정했다. 별도 원본 게임 파일을 확보하거나 원본 스프라이트를 복사한 것은 아니다.

- 560px 이상 가로 화면에서 식당 장면이 전체 가용 뷰포트를 사용하고 재화/메뉴를 가장자리에 배치한다. 세로 플레이도 유지한다. 100dvh와 safe-area inset을 사용한다.
- 전체화면은 사용자 버튼으로 요청하며 지원되는 브라우저에서만 가로 방향 잠금을 시도한다. 거부/미지원이면 수동 회전 안내를 보여준다. 전체화면 종료·페이지 이탈 때 방향 잠금을 해제한다. 금융 앱에는 방향 잠금을 적용하지 않는다.
- 기존 벡터 아트를 확장: 벽 색/아치 창문/목재 결/금속 조리대/흰 서빙대/붉은 의자/요리 접시, 머리 대비 작은 몸과 얼굴·머리묶음. 가구와 이동 인물을 셀 깊이로 함께 정렬한다.
- 원본 그래픽과 픽셀·프레임·메뉴 밀도가 동일하지 않다. 사용자의 저장 배치와 조리대 수를 유지하며 화면을 채우려고 가짜 조리대나 신규 요리를 추가하지 않았다. 기존 경제/타이머/동작 시간/저장 키·스키마를 변경하지 않았다.
- 레스토랑 집중 회귀9 통과: 기존7 + 세로/가로6개 크기·실제 터치·모달/뒤로·판매 중 회전 + 전체화면 거부/방향 잠금 미지원과 해제. 전체화면 API 실패 분기는 모의 API로 검증했으며 실제 Android/iOS의 방향 잠금·OS 안전 영역은 미검증이다.
- 최종 전체 CI 및 공개 배포 검증은 이 변경 PR 본문에 기록한다. 루트 index.html/sw.js, 금융 계산, 다른 게임은 수정하지 않는다.

**완료 범위는 재고 보충·조회·순차 소비·정산·다음 조리 흐름이다. 한 번 조리한 배치를 원작의 여러 접시로 나눠 파는 부분은 미완료다.** 정확한 수량·단가를 확보하지 못해 임의로 분할하거나 총 보상을 바꾸지 않았다. 손님 등장/식사 시간은 기존 보정값 유지. XP·고용·숙련·폐기·신규 메뉴는 추가하지 않았고 기존 구매 확장 레벨은 원작 XP 성장과 다르다.

### 저장과 복원
- 기존 v1/v2 저장 키 유지. v2 루트의 `service.version:1`을 읽고, 서빙 상태 변경 때만 `version:2`로 전환한다. `stock[i]`는 `{recipe,batches:[기존 배치 객체...]}`. 첫 실행 읽기만으로 기존 기록을 다시 쓰지 않는다.
- 코인/served/level/decor/조리 recipe·ends/roomLayout/루트 미지 필드 유지. 기존 재고 객체와 service/guest 미지 필드, 식사/퇴장/paid 상태 보존. 조리·음식 소비로 종료되는 항목은 기존 게임처럼 제거된다.
- 배치 추출과 guest.batch 전환을 한 JSON 쓰기로 처리. 지급/paid/phase도 원자적 변경이며 실패 시 이전 메모리·표시로 복원. 기존 이미 지급된 손님은 재지급하지 않는다. 재접속은 현재 연출 단계에서 다시 시작할 수 있으나 금액은 중복되지 않는다.
- 이전 저장본을 가진 다른 창에서 새 기록을 덮어쓰려 하면 거부하고 재접속 안내. 동시에 이미 실행 중인 구버전 엔진까지 소급 제어하는 기능은 아니며 여러 창을 통한 병행 영업은 권장 흐름이 아니다.
- 읽을 수 없는 원본/미지원 service 버전은 초기화하지 않는다. 금액을 임의 기본값으로 표시하지 않고 쓰기/조리를 막는다. 사용자가 기존 초기화 확인을 승인하는 동작은 유지한다.
- 금융/수박게임/루트 HTML·서비스워커 수정 없음. 게임 진입 때만 엔진 로드하며 숨김/편집/모달 동안 영업 중단, 조리는 기존 wall-clock 종료 시각 유지.
