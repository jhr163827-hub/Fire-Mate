## v1.6.0 첫 단위 · 도감/숙련과 반복 조작

- 기존 요리5종에 장면과 같은 SVG 음식 그림을 선택창·도감에서 재사용. 시간·재료비·접시별/전체 판매액·잠금 조건·완성 기록을 함께 표시한다. 이미지 파일/새 외부 의존성은 추가하지 않는다.
- 조리대 배지는 1분 미만 초, 1시간 미만 분:초로 읽는다. 실제 종료 시각과 비용·총 보상·XP 값은 그대로다.
- 요리사만 직접 그린 양쪽 머리묶음/검은 머리·눈웃음·붉은 상의를 다듬는다. 원본 게임 스프라이트를 확보/복사하거나 공식 라이선스를 확보했다는 주장이 아니다.
- 숙련은 완성 음식을 서빙대로 성공적으로 옮긴 횟수. 자체 기준3회(익숙한 요리)·10회(마스터). 배지는 기록/수집이며 시간·수익 보너스를 주지 않는다. 이 숫자는 원작 값이 아니다.
- 기존 동일 저장 키 아래 `cookbook:{version:1,recipes:[{completed:0},...]}` 를 첫 성공적 이동 때만 추가한다. 기존 완성 횟수는 추정하지 않는다. 루트/도감/각 요리의 미지 필드는 보존한다. recipe 인덱스·조리 중인 ends·기존 코인/판매/XP/시설·배치와 손님은 유지한다.
- 재고 추가·조리대 비우기·숙련 기록은 하나의 기존 transaction에서 저장한다. 실패 때 전부 복원되므로 재시도나 빠른 입력으로 숙련/음식이 중복 지급되지 않는다. 미래 도감 버전은 보존하고 새 조리/이동을 차단한다. 기존 열린 영업의 판매·정산은 도감 필드를 수정하지 않는다.
- 도감은 요리 목록에서 진입하고 뒤로가기로 이전 조리대 목록에 복귀한다. 원래 모달의 영업 일시정지와 초안 없는 조회 흐름을 사용한다.

검증 결과는 해당 PR 본문에 최신 CI·배포 결과와 함께 기록한다. 실제 휴대폰 성능·네이티브 회전·OS 안전 영역, 원작과 같은 속도/애니메이션은 미검증이다.

## v1.7.0 · 두 번째 직원 고용과 동시 서빙

재개 main `681efafa563338259f6df77308eb41e74c0fed81`. v1.6 이후 NIGHTFALL·수두쿠·시세 자동 기록이 추가됐으나 레스토랑 코드는 같았고, 열린 PR은 이전 WIP6뿐이었다. 새 main의 타 게임 파일을 유지하는 별도 브랜치에서 작업했다.

- 기존 기본 서빙 직원1명은 계속 무료이며 다시 구매하지 않는다. 추가 고용은 1회만 가능하고 급여·해고·유료 결제는 넣지 않는다. 실제 두 직원이 각자 한 접시를 운반해 두 테이블을 동시에 응대한다. 기존 조리 시간·메뉴 가격·접시 총보상·XP·숙련은 유지한다.
- 기존 확장 메뉴에서 직원 현황·해금/부족 금액·고용 비용을 확인한다. 고용 성공 후 버튼을 비활성화한다. 저장 실패 시 코인과 고용 상태를 함께 복원하고 재시도할 수 있다. 셰프 성장과 이전 시설 단계 어느 쪽으로도 고용이 열리며 시설/해금을 낮추지 않는다.
- 기존 동일 키 아래 `staff:{version:1,servers:2,assignments:{[guestId]:workerIndex}}` 를 고용 시 추가한다. 이미 유효한 v1 직원 기록이 있으면 미지 필드를 유지한다. 도입 전 기록은 읽기만으로 다시 쓰지 않고 기본1명으로 재생한다. 손님 객체의 기존 미지 필드를 새 담당자 필드로 덮어쓰지 않는다.
- 주문 담당자 배정과 접시 재고 차감을 한 transaction에서 저장한다. 운반→식사 전환 시 담당자를 해제하며, 코인/XP/paid 정산은 기존 식사 종료 규칙을 유지한다. 업데이트 전에 이미 운반 중인 주문은 기존 직원0이 이어받아 금액/지급 상태를 보존한다. 재접속에도 각 주문 담당자를 유지한다.
- 미지원 직원 버전/형식은 보존하고 새 고용·조리·영업 진행을 막는다. 오래된 창의 쓰기는 기존 저장 비교로 거부한다. 기본 인원 변경이나 고용 실패로 기존 레벨/작업/기록을 초기화하지 않는다.
- 렌더의 직원 상태를2개로 분리한다. 기존 첫 직원 DOM 식별자는 유지하고 추가 직원만 별도 인물로 그린다. 각각 경로·접시·복귀 상태를 유지하고, 두 직원 이동 때 작은 차선 간격을 둔다. 기존 모달/숨김/편집 중단과 모션 감소 처리를 유지한다. 원작 프레임/행동 속도 일치라고 주장하지 않는다.

### 저장과 배치 보호
- 기존 키 `firemate_arcade_restaurant_v2` 아래 `furniture:{version:1,nextId,items:[{id:'furn-N',sku,paid,location,position}]}` 를 첫 성공적 구매 때만 추가한다. 읽기/재접속만으로 기존 저장을 전환하지 않는다. 기본 가구·기존 decor 값을 구매 소유권으로 추정하지 않는다.
- 단조 증가 ID는 판매 후 재사용하지 않는다. location은 warehouse/placed/sold 중 하나. 판매된 개체도 기록과 미지 필드를 남겨 중복 판매와 ID 재사용을 막는다. 창고/판매 개체의 마지막 position은 기록으로 유지하며 장면 포함 여부는 location으로만 판단한다. 보유 수량에서 sold는 제외한다.
- 구매 코인+소유권, 판매 코인+sold, 보관 location, 배치 위치+roomLayout은 각각 기존 단일 JSON transaction으로 저장/복원한다. 실패하면 메모리·코인·소유권·장면을 이전 상태로 함께 복원한다. 배치 실패에는 초안을 남겨 재시도할 수 있다.
- 기존 root/roomLayout/positions 및 가구 기록의 미지 필드를 유지한다. 기존 조리 종료 시각·판매/레벨·XP·숙련·직원/담당자·배치와 다른 localStorage 키는 변경하지 않는다. 새 위치 기록은 개별 가구 position이 기준이며 과거 roomLayout에 남은 위치만으로 창고/판매 가구를 재생성하지 않는다.
- 미지원 furniture 버전/품목/중복 ID/잘못된 형식은 보존하며 구매·배치·판매·다른 transaction과 자동 서빙 쓰기를 막는다. 기존 명시적 전체 초기화는 확인을 거쳐야 한다. 오래된 창의 쓰기는 기존 원본 문자열 비교로 거부한다. 서버/멀티 프로세스 잠금을 새로 만든 것은 아니며, 이전 버전 엔진과 동시에 플레이하는 경우까지 무손실을 보증하지 않는다.
- 빈 칸·출입구·가구 충돌 외에 두 테이블/두 서빙대의 네 경로 조합, 조리대 접근, 현재 인물·요리사 위치를 검사한다. 배치 불가 칸은 빨강, 가능 칸은 초록. 가구 목록의 추가/제거도 렌더와 경로 캐시 키에 반영한다. 기존 무료 가구 이동 흐름은 유지하며 구매 장식이 있는 배치는 경로를 다시 검사한다.
