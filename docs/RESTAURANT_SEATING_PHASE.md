# 기능성 좌석 확장 구현 계약 (진행 중)

대상: `arcade/restaurant-engine.js`, `arcade/restaurant-room.js`, `arcade/restaurant.html`, 관련 CSS·Playwright 검사. 기존 금융·다른 게임은 수정하지 않는다.

## 현재 코드에서 확인한 제약
- v1.8의 `furniture` 버전1은 장식 3종만 허용하며, 미지원 품목은 저장을 중단한다. 새 좌석 SKU를 넣을 때 기존 기록 검증과 호환성을 함께 갱신한다.
- `service` 버전1~3은 `guests.length===2`, `stock.length===2`, `table<2`를 요구한다. 단순히 화면에 테이블을 추가해도 세 번째 손님은 나타나지 않는다.
- `restaurant-room.js`의 서비스 경로는 기본 식탁/의자 인덱스에 고정되어 있다. 새 좌석은 실제 배치와 출입·서빙 경로가 검증되어야 한다.
- 직원 수는 최대2명이다. 세 번째 손님은 두 직원의 작업이 끝날 때까지 기다려야 하며 담당자 중복이 없어야 한다.

## 구현·검증 완료 조건
1. 자체 밸런스 좌석 세트(식탁1+의자1)를 120코인에 한 번만 구매하고, 판매는 60코인으로 제한한다. 셰프 Lv2 또는 시설2에서 해금한다. 최대 추가 좌석 1세트.
2. 구매는 단일 저장 transaction으로 코인·소유권을 함께 저장하고 실패 시 복원한다. 기존 저장 키 `firemate_arcade_restaurant_v2`와 알 수 없는 필드는 유지한다.
3. 식탁과 의자를 함께 배치하며 두 구성요소가 모두 유효하고 출입·조리·서빙 경로를 막지 않아야 저장된다. 미완성 세트로는 손님 슬롯을 늘리지 않는다.
4. 기능성 좌석이 배치된 경우에만 세 번째 손님이 생성되고 착석·대기·서빙·식사·정산·퇴장한다. 기존 손님2명, 기존 재고·주문·보상·XP는 변경하지 않는다.
5. 세 번째 손님에 대한 직원 할당·이동 경로를 지원하되 최대 직원2명으로 순차 처리한다. 재접속 후 중복 정산하지 않는다.
6. 사용 중 좌석 세트의 보관·판매·이동은 거부한다. 배치 취소는 소유권과 코인을 되돌리지 않는다.
7. Playwright로 구매/취소/배치/영업/정산/재접속/동시 직원2명/저장 실패/구버전 데이터/모바일 320~430px를 검사한다.
8. 실제 테스트 통과와 CI·Pages 확인 전에는 구현 또는 배포 완료로 선언하지 않는다.

현재 이 문서는 작업 범위와 호환성 계약만 정의하며, 좌석 기능 자체는 아직 구현되지 않았다.
